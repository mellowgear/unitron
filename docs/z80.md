# Z80: the sound CPU's language and commands

This file covers the `unitron z80` commands: the Zilog assembly language they read and write, where
unitron differs from Zilog's manual, the instruction set, what the disassembler does, how the
result joins the main-CPU build, the error numbers, and the checks.

The NGPC has a second CPU for sound: a "Z80 compatible CPU core" with 4 KB of RAM (SNK *SysPro*,
"SOUND CONTROL CPU"; [snk/SysPro/SysPro.md](snk/SysPro/SysPro.md)). The main CPU stops it, copies a program into that RAM (main-CPU address
0x7000 is Z80 address 0000H), and starts it again. unitron reads and writes such programs with
three commands:

```
unitron z80 dis driver.bin                  # listing: address, bytes, instruction
unitron z80 dis driver.bin -o src/          # src/main.z80, which assembles back to the same bytes
unitron z80 dis driver.bin -o src/ --hints hints.txt --executed addrs.txt
unitron z80 asm main.z80 -o driver.bin [-I DIR] [--sym driver.sym]
unitron z80 asm main.z80 --equ driver.inc [--equ-base 0x7000] --db driver.db
unitron z80 roundtrip driver.bin [--hints FILE] [--executed FILE] [--workdir DIR]
```

The input of `dis` and `roundtrip` is the Z80 program alone (its first byte is Z80 0000H), not a
whole cartridge. The output of `asm` is the same kind of file. How the main CPU's code gets the
program into Z80 RAM is up to the game; `--equ` and `--db` (below, "Into the main build") write
the two files its asm900 source includes.

Sources (cited, never copied):
- **UM** = Zilog *Z80 CPU User Manual* UM0080, revision UM008011-0816 (2016). It is the source for
  every instruction, its operands and its codes. The page numbers are the printed ones; the PDF
  page is the printed page + 14.
- **ZM** = Zilog *Z80 Assembly Language Programming Manual* (January 1978). It is the source for
  the assembler language: statements, labels, numbers, expressions, pseudo-ops and error numbers.
  The page numbers are the printed ones; the PDF page is the printed page + 3 in chapters I-V and
  + 10 in the appendices.
- Rodnay Zaks, *Programming the Z80* (3rd ed.) and the HI-TECH ZAS manual were used only to
  confirm a reading of ZM.

## The syntax

Zilog's full style. The Z80 assembler has its own lexer and directives, so nothing is shared with
asm900, and a reader can tell the two kinds of source apart at a glance. "Where unitron differs
from ZM" below lists the exceptions. What `z80 dis` writes, and what `z80 asm` reads:

| Part | Spelling | Source |
|---|---|---|
| Mnemonics, registers, conditions | upper case: `LD A,(IX+05H)`, `EX AF,AF'`, `JP (HL)`, `OUT (0FFH),A` | UM p.39 (notation), tables 6-20 (p.42-64); ZM p.2, p.4 |
| Case | opcodes and keywords all capitals or all lower case (`ld a,b` is fine, `Ld` is not); labels are case-sensitive | ZM p.12 |
| Numbers | a leading digit and an optional base letter: `0FFH`, `101B`, `17Q`/`17O`, `12D`, `12` | ZM p.12-13 |
| Labels | start in column one (colon optional) or end with a colon; a letter, then letters, digits, `?` or `_` | ZM p.6-7 |
| Comments | from `;` to the end of the line | ZM p.6, p.12 |
| Current address | `$`, the address of the current instruction: `JR C,$+5` | ZM p.9 |
| Relative jumps | the operand is the target; the assembler computes the offset | ZM p.9 |
| Pseudo-ops | `ORG nn`, `label EQU nn`, `label DEFL nn`, `END`, `DEFB n`, `DEFB 's'`, `DEFW nn`, `DEFS nn`, `DEFM 's'` | ZM p.10-11 |
| Conditional assembly | `COND nn` ... `ENDC`, not nested | ZM p.11 |
| Include | `*Include filename` in column one, at most four levels deep (the main file is level one) | ZM p.13-14 |
| Strings | in single quotes; `''` inside is one quote: `DEFM 'It''s'` | ZM appendix A no. 13 (p.281) |
| Operators | unary `+ - .NOT. \ .RES.`; `**`; `* / .MOD. .SHR. .SHL.`; `+ -`; `.AND. &`; `.OR. .XOR.`; `.EQ. = .GT. > .LT. < .UGT. .ULT.` (that order of priority, then left to right) | ZM p.7-9 |

`DEFB` and `DEFW` take one value each (ZM p.10 shows only `DEFB n`, `DEFB s` and `DEFW nn`), so
`dis` writes one data byte per line. Runs of 8 or more printable characters become `DEFM` (63 at
most, ZM p.11), and runs of 8 or more zero bytes become `DEFS`.

A small example (more in tests/z80/, for example `asm-all/main.z80`):

```
PORT	EQU	0FFH
	ORG	0000H
Reset:	DI
	LD	SP,00C0H
	IM	1
	JP	Main
	ORG	0038H
Int38:	EX	AF,AF'
	INC	A
	OUT	(PORT),A
	EI
	RETI
Main:	JR	Main
	END
```

## Where unitron differs from ZM, and why

- **Label length.** ZM p.7 says only the first six characters of a label count. unitron counts
  them all. Cutting them short would silently merge labels, and `dis` doesn't rely on six-character
  names.
- **Operands are split at commas only.** ZM p.6 also allows spaces between operands and forbids
  spaces inside an expression (p.8). unitron accepts spaces inside an expression
  (`LD DE,1 .SHL. 4`) and needs commas between operands. `dis` never writes spaces in operands.
- **Arithmetic.** ZM p.8-9 says 16-bit arithmetic is used throughout and that an overflow such as
  `7FFFH+1` is an error unless it is inside `.RES.(...)`. unitron computes exactly and checks the
  final value of each field instead:
  - n (a byte): -128 to 255; d (a displacement): -128 to +127; nn (a word): -32768 to 65535 (UM p.39).
  - `.NOT.`, `.AND.`, `.OR.`, `.XOR.`, `.SHR.` and `.RES.` work on 16 bits, as ZM says.
  - A true comparison is 0FFFFH ("all ones", ZM p.8).

  So `LD HL,7FFFH+1` is accepted. Division by zero is error 10.
- **The one-character spelling of .OR.** ZM's operator table gives a one-character spelling for
  `.OR.`, but it is illegible in the available scan (Zaks's copy of the same table shows "I").
  unitron doesn't guess at it: write `.OR.`.
- **Characters in expressions.** ZM shows a quoted character only as the operand of `DEFB` (and
  `DEFM` for strings), so `LD A,'X'` is an error. Write `LD A,58H` instead.
- **DEFS** "reserves" bytes (ZM p.10). The output is a raw memory image, so unitron fills them
  with zeros. `dis` relies on this when it writes a run of zeros as `DEFS`.
- **The image.** It always starts at 0000H and ends at the highest byte written. Gaps are zeros. An
  `ORG` that goes back over bytes already written is an error, and so is any byte past 0FFFH: the
  Z80 has 4 KB of RAM (SysPro, "SOUND CONTROL CPU"). Mirrors and unmapped areas are unknown. An `EQU` may hold any value (for example the address of
  hardware outside the RAM).
- **A label on an ORG line** gets the address before the `ORG`.
- **Not supported yet:** `MACRO`/`ENDM` (ZM chapter III) is an error that says so. `GLOBAL` and
  `EXTERNAL` (relocatable modules) are unknown opcodes. `END` takes no operand.
- **Listing commands.** `*List`, `*Eject`, `*Heading` and `*Maclist` (ZM p.13) only shape a
  printed listing, which unitron doesn't write, so they are accepted and do nothing. Assembler
  commands may be in any case (ZM p.12).
- **Forward references.** A symbol used by `ORG`, `DEFS`, `DEFL` or `COND` must be defined
  earlier in the source. These lines decide where the code that follows goes. Everywhere else a
  label may be used before it is defined.

## Instructions

Only the instructions UM0080 documents are accepted: 696 forms, listed in `src/z80.cpp` with the
table and page each comes from (UM tables 6-20, p.42-64). The undocumented ones, such as `IXH`,
`SLL` (CB 30-37), `IN F,(C)` (ED 70), the unused ED codes and the extra copies of `NEG`, `RETN`
and `IM`, are not accepted. `dis` writes them as `DEFB` with the comment "not a documented Z80
instruction". The trace stops there, because what such a sequence does would have to be guessed.

Two forms have two encodings. UM p.103 and p.108 give `LD dd,(nn)` and `LD (nn),dd` (ED 4B/ED 43
plus dd) for all four pairs, HL included, and UM p.102 and p.107 also give the one-byte forms
`LD HL,(nn)` (2A) and `LD (nn),HL` (22). The assembler always picks the shorter code. `dis` writes
the ED 6B and ED 63 encodings as `DEFB` with the instruction in a comment, so that the bytes come
back the same.

`RST p` is written in hex (`RST 38H`); `BIT`, `SET`, `RES` and `IM` numbers in decimal.
Displacements are written with their sign, in hex: `(IX+05H)`, `(IY-01H)`. `(IX)` alone means
`(IX+0)` (UM p.29, the bubble sort listing) except in `JP (IX)`.

ZM p.6 counts "694 legitimate combinations of opcodes and operands", and its listing (appendix
B, p.284-295) has 694 statements. unitron's table has 696; the difference is in `LD` (ZM's
statements 231-360 are 130 `LD`, unitron has 132), and which two are extra is not known (open).
All 696 encodings agree with the AS assembler (see "Checks"). The instruction headings of ZM
chapter VI and UM0080 (`IN A,(n)`, `OUT (n),A`, `IN r,(C)`, `OUT (C),r`, `EX AF,AF'`, `JP (HL)`,
`RST p`) are spelled the same.

## What `z80 dis` does

- **Tracing.** It follows the code from the Z80's fixed entry points: 0000H after reset (UM p.7),
  0038H, the mode 1 interrupt, and 0066H, the nonmaskable interrupt (UM p.19). It traces all
  three, with no detection of the `IM` mode. It also starts from any address in `--executed FILE`
  (hex addresses) and from `code` lines in `--hints FILE`.
- **How the trace follows instructions.**
  It continues after calls, `RST` and conditional jumps; it stops at `JP`, `JR`, `RET`, `RETI`,
  `RETN`, `JP (HL)`/`(IX)`/`(IY)` and at an undocumented sequence. It never decodes a byte twice:
  a jump into the middle of an instruction stays inside that instruction.
- **Hints.** A hints file has the same format as on the main CPU (`language.md`, "Trace hints"):
  `code ADDR [NAME]` adds an entry point; `data START END` keeps the trace out of START..END-1.
  `pointers` lines are an error here (main CPU only).
- **Labels.**
  - `Reset`, `Int38` and `Nmi` name the entry points (our names for UM's vectors).
  - `Rst08` ... `Rst38` name `RST` targets (UM p.292).
  - A hint's NAME names its address.
  - Every other jump or call target gets `L` plus the address (`L01E6`).
  - A memory operand that points into the image gets a label too. When that address is inside an
    instruction, the operand is written as that instruction's label plus k: for example
    `LD (L0516+1),A` for code that rewrites its own operand. The bytes then still match if
    instructions move.
  - `DriverEnd` names the end of the image (the address after its last byte). The NGPC sound
    drivers keep their data right after their code and hard-code those addresses (up to 6 bytes
    past the end), so a memory operand or a 16-bit immediate (`LD HL,nn`) from the end up to 15
    bytes past it (a margin) is written `DriverEnd+k`, and a data word that holds the image size
    is written `DEFW DriverEnd` (it could be a coincidence). The label is written only when
    something refers to it. A jump or call past the end stays a number.
- **Immediates inside the image stay numbers.** `LD HL,00C0H` may be an address or a count, and
  nothing in the instruction says which. A source that moves code must label such an operand by
  hand.
- **Everything else** is data (`DEFB`, `DEFM`, `DEFS`, as above).
- **Numbers that stay numbers.** Addresses outside the image stay numeric: the hardware the
  drivers use (4000H, 4001H, 8000H, 0C000H, port 0FFH) has no name in any source, and neither do
  the main-CPU ports 0xB8, 0xBA and 0xBC (`OPEN.md`).

## Into the main build: `--equ` and `--db`

The main CPU sees Z80 RAM at 0x7000 (SNK *SysLib*, "LINK COMMAND FILE", [snk/SysLib/SysLib.md](snk/SysLib/SysLib.md):
`z80 :org=0x7000 len=0x1000`), so
Z80 address n is main-CPU address 0x7000 + n. `z80 asm` writes two files for the main CPU's
asm900 source:

- `--equ FILE`: every label as an asm900 `equ` line at its main-CPU address, sorted by address:
  `Tick_seen equ 0x7071`. Main-CPU code then writes `ld A,(Tick_seen)` instead of `(0x7071)`, and
  the number follows the Z80 source. `--equ-base N` changes 0x7000. `EQU` and `DEFL` names are
  left out (they are constants such as a port number, not addresses in the image). A label that
  can't be an asm900 name is an error, and nothing is written: one with `?` (ZM allows it, asm900
  doesn't), or an asm900 reserved word such as `XHL`. Z80 labels may clash with main-CPU names;
  there is no prefix option. These names come from the program's own Z80 source, not from
  hardware documents, so the hardware-names rule (`hardware-names.md`) doesn't apply to them.
- `--db FILE`: the image as asm900 `db` lines, 16 bytes per line: the same lines `unitron bin2db`
  writes for the image, with a header that names the Z80 source. It has no label: the main source
  puts one in front of the `$include`.

```
$include "driver.inc"           ; the Z80 labels, at 0x7000 + n
...
	ld	A,(Tick_seen)
...
Z80Driver:                      ; anywhere in ROM; the main CPU copies it to 0x7000
$include "driver.db"
```

The case `tests/z80/equ-main` assembles a small Z80 program with both options and then a main-CPU
file that includes both files.

## Error numbers

`file:line: error EN: message`, with ZM's numbers (appendix A, p.280-283):

| N | ZM's name | Examples |
|---|---|---|
| 2 | name contains invalid characters | a label `1abc`, or a register name as a label |
| 3 | invalid opcode | `FROB`, `Ld` (mixed case) |
| 4 | invalid number | `0AB` (no H), `19Q` |
| 5 | invalid operator | `.FOO.` |
| 6 | syntax error | a missing operand, a `DEFM` longer than 63 characters |
| 8 | undefined symbol | |
| 9 | invalid operand combination | `LD (BC),B`, a register inside an expression |
| 10 | expression out of range | `LD A,256`, `(IX+128)`, `JR` too far, `IM 3`, `RST 09H`, `BIT 8,A`, division by zero |
| 11 | multiple declaration | a label defined twice |
| 13 | unbalanced quotes | `DEFB 'ab` |
| 14 | assembler command error | an unknown `*` command, an include file not found |
| 17 | include nested too deep | |

Errors without a number are unitron's own limits: a byte past 0FFFH, a byte written twice, macros.
No output is written when there are errors.

## Checks

- **`z80opspace`** (`tests/vectors/z80opspace.tsv`): every first byte, every second byte after
  CB, ED, DD and FD, and every fourth byte after DD CB d and FD CB d, each with four sets of
  operand values (7,168 inputs). Every documented instruction is decoded, written as text, and
  assembled back to the same bytes; the ED 6B/ED 63 forms assemble to the shorter code;
  everything else stays undecoded. The decoded text of every input is frozen in the file, so any
  change shows up as a diff.
- **Cases** (`tests/z80/`, `tests/README.md`): small programs of our own for every
  pseudo-op, number base and operator, the errors above, `dis` with hints, undocumented bytes and
  addresses inside instructions, `DriverEnd` references (`end-*`), `roundtrip`, and the
  command-line errors (`tests/cli/z80-*`). The `datasheet` test checks 184 encodings against
  UM0080's own examples (`tests/datasheet/z80.txt`).
- **`z80shift`** (tests/cpp/z80.cpp): proves that the labels carry the addresses. It writes the
  source of a program of our own, puts one `NOP` in front of the first instruction whose operand
  is rewritten (else in front of `DriverEnd`), assembles it and checks the result byte for byte:
  every jump, call and memory operand into the image at or after the `NOP`, every `DriverEnd+k`
  reference and every `DEFW DriverEnd` has moved by one, and nothing else has changed. The program
  has each kind of reference, and references that must not move (an immediate count, a hardware
  address, `RST`, operands before the `NOP`).
- **`z80rom`** (`tests/vectors/z80_rom_hashes.txt`): the sound drivers of two commercial ROMs,
  each cut out of its ROM by offset and length and checked by sha256. `z80 dis`, `z80 dis -o` and
  `z80 roundtrip` run on each, every output is compared by sha256, and both round trips are
  byte-identical. The `z80shift` check runs on each driver too (pass or fail only; nothing is
  stored). A ROM that is absent (`$UNITRON_ROM`, `$UNITRON_ROM2`) is skipped.
- **Cross-check with AS** (Alfred Arnold's Macro Assembler AS, run by hand; not part of the build
  or the tests). One AS source with all 1,218 distinct instruction texts of `z80opspace.tsv`
  (all 696 forms with several operand values, in exactly the spelling `dis` writes) gives the
  same 3,138 bytes as unitron's table, with no errors: an independent assembler reads UM0080's
  instruction set, and unitron's operand spelling, the same way.
